## Проект

PoC офлайн-приложения (Edge AI) для скрининга **риска** анемии по фото глаза: нижняя пальпебральная конъюнктива + склера. Диагноз не ставим. Выход: риск (низкий / средний / высокий), ориентировочный диапазон Hb, «по какой ткани и почему», PDF-отчёт для врача. Команда пишет по-русски: отвечать по-русски, кратко, цифрами, без воды.

## Пайплайн

фото → найти глаз → сегментировать конъюнктиву и склеру → нормализовать цвет → модель → QC → риск + диапазон Hb + причина.
- **Сегментация**: обученная сеть (U-Net / DeepLabV3+ на MobileNet / EfficientNet-lite, `segmentation_models_pytorch`), не пороги. Конъюнктива: маски врачей Eyes-defy-anemia + наши. Склера: внешний датасет с масками или полуавтоматическая разметка командой. Аугментации: цветовая температура 2700–7500 K, экспозиция, гамма, JPEG, шум, размытие, масштаб, поворот. Запасной режим: пользовательская обводка века, анализ только внутри неё.
- **Нормализация цвета**: (a) ArUco-карточка в кадре → матрица 3×3 (PDF карточки генерирует код); (b) без карточки — по склере того же снимка; (c) признаки «конъюнктива относительно склеры». Эффект доказывается стресс-тестом: один глаз под разным искусственным светом → разброс признаков и Hb до/после.
- **Модель Hb/риска**: сравнить цветовые признаки + бустинг/Ridge, малую CNN по вырезу (transfer learning) и ансамбль; выбор только по метрикам на отложенных пациентах. Калибровка вероятности; порог риска — на высокую чувствительность.
- **Выбор ткани**: по ожидаемой ошибке каждого метода из валидации и качеству снимка. Согласуются — объединить; расходятся — более надёжная + причина пользователю.
- **QC**: непригодный или нетипичный (OOD) снимок → «оценка ненадёжна, переснимите» **без цифры Hb**.
- **Экспорт**: ONNX/TFLite + тест совпадения с PyTorch.

## Валидация (главное требование)

- Только `GroupKFold` по пациенту или отдельный тест; пороги и калибровка подбираются внутри обучающих фолдов. Утечка train/test недопустима.
- Отчёт раздельно: взрослые (Eyes-defy), дети (CP-AnemiC), наши телефонные фото.
- Метрики: IoU/Dice сегментации на невиданных пациентах; MAE Hb (г/л) + Bland–Altman; AUC; чувствительность/специфичность с 95% ДИ при выбранном пороге; стресс-тест «другой свет».
- Синтетика — только проверка, что код запускается. Метрики на синтетике никогда не выдавать за точность (так было в v9–v10: ±4–6 г/л и IoU 91% — недостоверно).
- Пороги не подгонять под отдельные фото (в v10 подогнаны под 3–4 снимка).
- В ответах — таблица из вывода `scripts/evaluate.py`, не пересказ.

| Метрика | База (v10, Eyes-defy) | Цель |
|---|---|---|
| IoU конъюнктивы с разметкой врачей | 0,33 | ≥ 0,75 |
| MAE Hb | ≈ 12–13 г/л | — |
| AUC | 0,855 | ≥ 0,85 |
| Чувствительность / специфичность | 0,14 при Hb < 100 г/л | ≥ 0,80 при спец. ≥ 0,70 |
| Разброс Hb одного глаза при разном свете | — | ≤ ±5 г/л |

Цель не достигнута — сказать прямо, с цифрами и гипотезами. Не подгонять.

## Colab

Команда открывает `notebooks/colab_train.ipynb` в VS Code и подключает к Colab-рантайму расширением Google Colab. Claude правит блокнот и пакет, пушит в GitHub. Ячейка 1: клон/обновление репо (токен из Colab Secrets), зависимости, скачивание датасетов; дальше только вызовы `scripts/`. Модели сохраняются в `models/` и скачиваются файлом. Ячейки запускает команда: каждый раз писать, какие ячейки и в каком порядке. Лёгкие проверки (pytest, малые прогоны) Claude запускает сам.

Ловушка: sklearn ≥ 1.9 HistGradientBoosting с `sample_weight`/`class_weight` в ~30 раз медленнее; балансировать оверсэмплингом.

## Порядок работы

1. Начать в plan mode: план по этапам с оценкой времени и списком того, что нужно от команды (доступы, разметка, фото). Ждать одобрения.
2. Этапы: (0) структура, данные, тесты формул → (1) `evaluate.py` и честный baseline текущего подхода → (2) сегментация → (3) нормализация цвета → (4) модель Hb/риска → (5) выбор метода и QC → (6) демо и экспорт.
3. После каждого этапа: pytest + evaluate, таблица «было/стало», git commit, отчёт 5–10 строк. Метрика ухудшилась → дальше не идти, сначала разобраться.
