# Фантом-эксперимент (съёмка 21–22.11.2026)

**Вопрос:** если снимать одну и ту же шкалу «бледно-розовый → тёмно-красный» разными телефонами при разном свете,
сохраняется ли порядок образцов по a* и Erythema Index и насколько расходятся цифры — до и после коррекции по
цветовой карточке?

**Что это НЕ проверяет:** связь цвета с гемоглобином (на бумаге нет крови), сегментацию века, модель риска.
Модель и пороги риска не меняются. Людей в эксперименте нет → этика не нужна.

Время: печать 15 мин, съёмка ≈ 1 ч (+30 мин желатин, по желанию), анализ в Colab 5 мин.

## 1. Что нужно

- Цветной принтер (лазерный или струйный), **матовая** бумага A4 (обычная офисная подойдёт; глянец даёт блики).
- Файл карточки: `phantom_card.pdf` (в общей папке проекта `phantom/`, или сделать заново:
  `python scripts/phantom_analysis.py card --out phantom_card.pdf`).
- 2 телефона (обозначим `p1`, `p2`; лучше разных марок). Запишите модели.
- 3 источника света: `okno` — дневной свет у окна (без прямого солнца на листе); `lampa` — тёплая лампа
  (жёлтая, 2700–3000 K), верхний свет выключен; `led` — белый холодный свет (потолочная LED/офисная лампа).
- Ровный стол, линейка.

## 2. Печать

1. Открыть `phantom_card.pdf` → Печать.
2. Масштаб: **«Фактический размер» / «100%»**. Не «Вписать в страницу». Ориентация — альбомная.
3. Качество: «Высокое», цвет, без экономии тонера.
4. Проверить линейкой полоску «50 mm» внизу листа: должно быть 50 мм (± 1 мм). Иначе перепечатать.
5. Печатаем **один** лист и снимаем только его (у другого листа будут другие цвета). Не сгибать.

## 3. Настройка телефонов

- Формат JPEG. iPhone: Настройки → Камера → Форматы → **«Наиболее совместимые»** (иначе HEIC — скрипт его не
  читает). Android: обычная камера, режим «Фото».
- Без вспышки, без фильтров, без «портрета», без зума (×1). Остальное — авто, как у обычного пользователя.

## 4. Съёмка: 2 телефона × 3 света × 8 снимков = 48

Для каждой пары «телефон + свет»:
1. Лист на столе ровно. Свет горит только нужный (у окна — шторы открыты, лампы выкл.; `lampa`/`led` — вечером
   или со шторами).
2. Телефон над листом на 30–40 см. **Все 4 чёрных квадрата в кадре**, лист занимает ~ 2/3 кадра.
3. Нет тени от телефона и руки, нет бликов на цветных квадратах (если блик — чуть наклонить телефон).
4. Нажать на лист для фокуса, сделать снимок. Между снимками немного сдвигать телефон (угол 0–20°, расстояние).
5. 8 снимков → следующая пара.

Порядок: `p1 okno` → `p2 okno` → `p1 led` → `p2 led` → `p1 lampa` → `p2 lampa` (одна позиция света — оба
телефона подряд, чтобы свет не успел измениться).

Запишите в таблицу (заметки): дату, время, модели телефонов, какие лампы (если на упаковке есть K — записать).

## 8. Что считает скрипт

Для каждого снимка: 4 маркера → гомография → медиана цвета центральных 60% каждого квадрата. Три варианта:
- `raw` — как снял телефон;
- `wb` — баланс белого по серым полям (3 коэффициента в линейном RGB);
- `ccm` — матрица 3×4 в линейном RGB по 12 эталонным полям карточки (нужно ≥ 8 полей без пересвета, иначе
  снимок в `ccm` не попадает — это видно в столбце `n_photos`).

По каждому образцу: a* (CIELAB, D65) и EI = log10 R − log10 G (те же формулы, что `anemia/color.py`).
- `monotone` — доля снимков, где a*/EI строго растут от S1 к S8 (Спирмен = 1); `rho_min` — худший снимок.
- `sd_step` — разброс одного образца по всем снимкам в долях шага между соседними образцами. Главное число.
- `light_sd_step` / `phone_sd_step` — отдельно разброс из-за света и из-за телефона.
- `cv_pct` — SD/среднее, %; `card_dE` — остаточная ΔE карточки после коррекции.

## 9. Критерии успеха (зафиксированы 18.11.2026, до съёмки; по фото не подбираются)

Для `ccm`, метрика a*: порядок верен на **≥ 90 %** снимков, разброс **≤ 0,5 шага**, карточка применилась
к **≥ 80 %** всех снимков в папке (включая те, где лист не найден), и `sd_step(ccm) < sd_step(raw)`.
Образец с > 20 % пересвеченных пикселей (блик) в сводку не идёт — их число в `n_clipped_samples`.
Шаг шкалы: a* ≈ 5 единиц на образец. «Различимы» значит «различимы при таком шаге»; разница «норма / анемия» у
конъюнктивы может быть меньше — это не чувствительность к Hb. В `report.md` пишется хэш коммита кода.

Проверка кода на синтетике (`python scripts/phantom_analysis.py demo --out …`) — **не результат**: свет там
смоделирован, на настоящих телефонах будет хуже (автобаланс, HDR, тон-кривая, блики).

Если не пройден — это тоже результат: пишем цифры как есть и причину (какой свет / телефон, блики, пересвет).

## 10. Честные ограничения (говорить на защите)

- Фантом проверяет камеру и коррекцию цвета, **не точность по Hb**. Связь с Hb — только пилот с анализом крови.
- Бумага отражает свет, ткань просвечивает; желатин ближе, но тоже не кровь.
- Абсолютные a*/EI зависят от принтера и бумаги; сравниваем только разброс и порядок.
- Модель риска обучена без карточки (Eyes-defy): коррекция по карточке в модели не используется.
- 2 телефона и 3 света — малая выборка; вывод — «на этих условиях», не «на любом телефоне».
- Цветовой профиль снимка (у iPhone — Display P3) не учитывается: файл читается как sRGB. Карточка это частично
  исправляет (матрица), без карточки разница телефонов завышена.
