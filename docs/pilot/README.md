# Пилот HemaVision: что делает код (протокол v1.1 от 2026-11-21)

Полный протокол («План пилота и протокол сбора данных, версия 1.1») и формы лежат в закрытой папке проекта, не в
этом публичном репозитории. Здесь — только то, что касается кода. Пилот **не начат**, этического одобрения **нет**,
партнёр (Медицинский университет Караганды, МУК) — **потенциальный**, участие не подтверждено.

## Что это за исследование
- **Исследование осуществимости** (feasibility study), не клиническая валидация. Первичные исходы: доля пригодных
  снимков и повторяемость. AUC, чувствительность и специфичность — только предварительные, с 95% ДИ.
- Первые 60 участников этапа 1 — **пробный этап**: по ним смотрят только долю анемии и долю пригодных снимков, чтобы
  пересчитать объём. Ответы модели на пробном этапе не открываются.
- Набор **последовательный**: все подряд взрослые, сдающие ОАК в клинике, без отбора по Hb.
- Ориентир — **30 оцениваемых случаев анемии**: анемия по ВОЗ 2011 с учётом пола (Ж < 120, М < 130 г/л), Hb из ЛИС того
  же дня и сохранённый снимок 1 (прошёл проверку качества приложения не более чем за 3 попытки). Отказ модели
  («переснимите» на сохранённом снимке) на счёт не влияет. N = 30 / (доля анемии × доля участников с пригодным
  снимком 1): ≈ 120 при 25% анемии и всех пригодных, ≈ 140 при 85% пригодных. Окончательный объём и верхний предел
  набора не утверждены; правило остановки записывается до первого участника.
- Не включаются: несовершеннолетние (< 18) и беременные.
- Результат HemaVision участнику **не показывается**.
- Данные **псевдонимизированные** (не «обезличенные»): фото глаза — биометрический признак.
- Отчётность — по чек-листу STARD 2015.

## Роли и доступ к данным
| Кто | Что видит и делает в данных | Чего не видит |
|---|---|---|
| Врач-исследователь клиники (ответственный исследователь; ещё не определён) | хранит список «код ↔ пациент», выгружает Hb из ЛИС, запускает `scripts/merge_lis.py` | — |
| Ученики | снимают, вносят снимок и анкету без ФИО в приложение сбора (`--pilot 1`) | ФИО, ИИН, ЛИС, Hb участников этапа 1 |
| Школьный руководитель | организация от школы, контроль соблюдения протокола | медицинских решений не принимает, к данным доступа не требуется |

## Два идентификатора
- **Код участника** — `P` + 6 символов, случайный, генерирует приложение. Это значение колонки `patient_id` во всех CSV
  исследования (`photos.csv`, `hb_lis.csv`, `hb.csv`). Название колонки историческое, менять его нельзя: его читают
  `merge_lis` и `anemia.data.load_phone`.
- **Идентификатор пациента в клинике** (ФИО, ИИН, номер карты или пробы в ЛИС) — только в списке «код ↔ пациент» и в
  подписанных согласиях у врача-исследователя. В CSV исследования не попадает: `merge_lis` принимает в `patient_id`
  только код вида `P` + 6 символов, иначе ошибка и файл не создаётся.

## Приложение сбора
```bash
pip install -e ".[app]"
python app/collect.py --pilot 0 --data <папка этапа 0>   # этап 0 (отработка): Hb с бланка участника допустим
python app/collect.py --pilot 1 --data <папка этапа 1>   # этап 1: поля Hb нет
```
- Только локально на зашифрованном ноутбуке; `--share` с `--pilot` запрещён. Папка `--data` — **вне** клона
  репозитория (в `.gitignore` закрыта только `data/`). Этапы 0 и 1 — в разных папках: данные этапа 0 в анализ этапа 1
  не входят.
- В обоих режимах пилота: только 18+, беременные не включаются; ответ модели не считается и не показывается.
- `--pilot 1`: запись → `<data>/pilot/images/`, `masks/`, `photos.csv` (колонки `anemia.collect.PILOT_COLUMNS`,
  без `hb_g_l` и `lab_gap_days`). Если в записи окажется Hb, она не сохраняется. Счётчик в окне — без Hb и без
  доли анемии.

## Hb из ЛИС (только врач-исследователь)
1. Врач выгружает `hb_lis.csv`: `patient_id, hb_g_l, lab_gap_days` (+ необязательно `unit`, `blood_time`, `analyzer`).
2. На своей зашифрованной копии:
   ```bash
   python scripts/merge_lis.py --photos <копия>/pilot/photos.csv --lis <папка врача>/hb_lis.csv \
       --out <папка врача>/phone/hb.csv
   ```
3. Результат — `hb.csv` в формате `anemia.data.load_phone`. Файл не перезаписывается и не может лежать в папке данных учеников
   (ни в `pilot/`, ни рядом с ней). Участники без Hb, с анализом не в тот же день и строки ЛИС без снимка не теряются: скрипт печатает их
   коды (без значений Hb) для блок-схемы STARD.

Модель, веса, признаки, пороги, правила отказа и медицинская логика этим кодом не затрагиваются.

## Открытые вопросы (не решены)
1. Нужно ли одобрение комиссии по биоэтике для этапа 0 — решает научный руководитель.
2. Кто будет ответственным исследователем со стороны клиники — не определён.
3. Окончательный объём выборки и правило остановки (верхний предел участников и срок) — не утверждены.
4. Скрипта «замороженная модель → фото пилота → таблица исходов» ещё нет (`evaluate.py --dataset phone`
   переобучает модель); его пишут и проверяют на синтетике до того, как кто-то увидит ответы модели.
5. Цветовая карта: маленькой карты в кадре нет (код 23.10 потерян), решение не принято. Контрольный снимок A4 в начале и
   в конце сеанса — только контроль условий съёмки, снимки по нему не исправляются; индивидуальная цветовая коррекция
   возможна только по карте в кадре и только во вторичном анализе.
6. Процедура защиты данных, срок хранения и действия при возможной утечке — не утверждены врачом-исследователем и
   клиникой.
7. Веса модели для заморозки не получены (см. таблицу выше).
8. Использование фото этапа 0 для обучения сегментации — только при отдельной отметке в согласии; допустимо ли это без
   решения комиссии по биоэтике, решает научный руководитель.

Протокол не готов к проведению исследования, пока не получены этическое одобрение и согласие клиники-партнёра.
