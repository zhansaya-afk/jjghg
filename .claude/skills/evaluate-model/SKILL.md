# evaluate-model

1. Запусти `python -m pytest -q` и покажи вывод. Красные тесты → сначала чинить.
2. Запусти `python scripts/evaluate.py --data <dir> --tag <этап>_<что_менялось>` на каждом
   доступном наборе (`--dataset eyes_defy`, `cp_anemic`, `phone`; по умолчанию — все из
   `<dir>/manifest.csv`). Смоук-прогон — с `--no-history`. Eyes-defy недоступен в облаке Claude:
   тогда написать команде, какие ячейки `notebooks/colab_train.ipynb` запустить, и ждать вывод.
3. Разбиение только GroupKFold по пациенту (фолды из манифеста, не пересчитывать); порог риска
   и калибровка подбираются внутри обучающих фолдов.
4. Выведи таблицу ≤ 15 строк из вывода скрипта, отдельно взрослые / дети / телефон:
   n, MAE г/л, AUC, чувствительность и специфичность (95% ДИ), IoU/Dice с масками врачей,
   «свет ±г/л».
5. Сравни с прошлым прогоном из `results/metrics_history.csv` (тот же `task, dataset, method`):
   столбцы «было (тег) / стало (тег) / Δ / цель». Перекрытие ДИ → «в пределах шума».
   Скрипт сам дописывает новую строку; старые строки не трогать.
6. Ключевая метрика ухудшилась вне ДИ → дальше не идти: гипотезы причин и что проверить.
   Цель не достигнута — сказать прямо, с цифрами.
7. Никогда не сообщай метрики на синтетических данных и не подгоняй пороги под отдельные фото.
8. Коммит: код + `results/metrics_history.csv`; `data/`, `models/`, OOF-предсказания — не в git.
