# error-analysis

Вход — OOF-предсказания последнего прогона `scripts/evaluate.py` (`<data>/results/oof_<tag>_*.csv`). Нет их → сначала `/evaluate-model`.
Код — `scripts/error_analysis.py` (нет — создать; логика в `anemia/`, скрипт только вызывает).

1. **Маски врачей vs автоматические** (Eyes-defy): та же Hb-модель на маске врача (потолок) и на нашей
   (`segment_baseline`, `regions.find_conj`, обученная сеть). Таблица: AUC, MAE, чувствительность — разница = потеря от сегментации.
2. **Матрица ошибок** по классам риска (низкий / средний / высокий) и бинарно при выбранном пороге; отдельно `Hb < 100 г/л`.
3. **20 худших снимков** по |Hb − прогноз|: фото, маска врача, наша маска, IoU, Hb, прогноз → `results/errors/<tag>/`
   (PNG + `worst.csv`). Это медицинские данные: `results/errors/` в `.gitignore`, не коммитить и не отправлять наружу.
4. **Разбивка ошибок**: по датасету, полу, возрастной группе, яркости (L* склеры/кадра, терцили), IoU маски, качеству снимка.
   Таблица: n, MAE, AUC, чувствительность; малые группы (n < 15) помечать «мало данных».
5. Итог — ≤ 15 строк: где теряется больше всего, 2–3 гипотезы, какой эксперимент проверит (→ `/run-experiment`).

Не подбирать пороги и не исключать «плохие» снимки по результатам этого анализа на тех же фолдах.
